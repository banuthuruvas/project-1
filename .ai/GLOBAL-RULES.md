# Global application rules

Rules version: 2026.08.10.1

These rules apply to every NIE application. Feature dossiers add requirements; they never weaken this file. AI agents are responsible for implementation and evidence, while standard compilers, linters, tests, analyzers, and security scanners provide deterministic signals.

## Rule status vocabulary

| Status | Meaning |
| --- | --- |
| pass | Requirement is implemented and supported by the required evidence. |
| fail | Requirement is applicable and missing, broken, or contradicted. |
| not-applicable | Requirement does not apply; a concrete product or architecture reason is recorded. |
| manual-review | Evidence needs an authorized human decision or external environment. It is not a pass. |
| approved-exception | A risk owner approved a time-bounded exception with remediation and expiry. |

## Required standard gates

- C#: dotnet format in verification mode, warnings-as-errors build with the configured Roslyn analyzers, xUnit tests, architecture tests, PostgreSQL integration tests where persistence semantics matter, and coverage evidence for changed critical code.
- Vue and TypeScript: ESLint, vue-tsc, Vitest component/unit tests, and Playwright for critical routes, access, responsive behavior, and user workflows.
- Dependencies and security: locked restores, vulnerability/dependency scanning, secret scanning, and CodeQL or an equivalent maintained static analyzer in the hosting platform.
- Delivery: build deployable artifacts, validate migrations and configuration, and verify health/readiness behavior before promotion.

These gates are executed, not merely asserted. `.github/workflows/ci.yml` runs the language, test and coverage-threshold gates on every push and pull request; `.github/workflows/quality-deep.yml` runs mutation testing and CRAP risk-hotspot analysis on a schedule; `.github/workflows/e2e.yml` runs the browser suite against a deployed environment. `.husky/pre-commit` keeps format, lint and build fast locally and `.husky/pre-push` runs the suites before code leaves the machine. An agent claiming a gate passed must cite the command and its result, and removing or weakening any of these workflows to make a change pass violates NIE-GOV-003.

`docs/test-strategy.md` records the per-application test matrix, coverage targets and current floors. Update it whenever a gate, threshold or test layer changes.

A deterministic check may detect a problem but cannot issue the complete architectural verdict. The implementing AI and independent verifier must inspect behavior, intent, domain context, and evidence.
